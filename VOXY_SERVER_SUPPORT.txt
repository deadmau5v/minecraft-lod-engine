================================================================================
                         VOXY SERVER SUPPORT SURVEY
================================================================================

Scope
-----
This note records the server-side options for distributing Voxy terrain data.
The findings were verified against the upstream source repositories and project
READMEs available at the time this branch was prepared.

Terminology
-----------
Voxy rendering is always performed on the client GPU. A server component does
not render OpenGL frames. It reads or generates terrain, converts it to a Voxy-
compatible voxel representation, caches it, and transfers it to Voxy clients.


RECOMMENDED PAPER / PURPUR PLUGIN
---------------------------------
Project:  LOD Server Support (LSS)
Source:   https://github.com/VoX/lod-server-support
Release:  https://github.com/VoX/lod-server-support/releases
Modrinth: https://modrinth.com/plugin/lod-server-support
License:  MIT

LSS is the closest Voxy equivalent to DHSupport. It provides:

* Paper and Purpur server plugin builds.
* Experimental Folia support.
* Fabric server/client builds and selected NeoForge builds.
* Direct Anvil chunk reads and optional missing-chunk generation.
* Voxy-compatible full 3D voxel-column transfer.
* Per-player and global bandwidth controls.
* Dirty-column notifications after world edits.
* Optional compressed SQLite LOD store for repeated requests.
* Region-summary synchronization, anti-xray handling, and transport pacing.
* Coexistence with a Distant Horizons server plugin on the same server.

Clients must install both Voxy and the LSS client mod. Installing only the Paper
plugin is insufficient because Voxy itself does not implement the LSS protocol.

For the existing Purpur server, LSS is the recommended solution. The native
RocksDB output generated by this repository is intended for Voxy/VoxyServer and
is not an import format for LSS.

Suggested conservative Purpur configuration:

    {
      "enabled": true,
      "lodDistanceChunks": 512,
      "mbPerSecondLimitPerPlayer": 25.0,
      "mbPerSecondLimitGlobal": 75.0,
      "enableChunkGeneration": false,
      "maxConcurrentDiskReads": 4,
      "dirtyBroadcastIntervalSeconds": 10,
      "lodYieldsToVanillaTransport": true,
      "enablePingBackstop": true,
      "enableSendPacing": true,
      "enableRegionSummaries": true,
      "lodStore": "on",
      "lodStoreResweepSeconds": 0,
      "xrayObfuscation": "auto"
    }

Operational notes:

* Configuration path on Paper/Purpur:
      plugins/LodServerSupport/lss-server-config.json
* Use /lsslod stats and /lsslod diag to inspect transfers and queue pressure.
* Use /lsslod store status to verify cache health and hit rates.
* LSS store backfill is not available on Paper. The store warms as terrain is
  served. Fabric has a background backfill implementation.
* Setting enableChunkGeneration=false prevents LSS from expanding the world.
* A lower maxConcurrentDiskReads value protects vanilla region I/O. Four is a
  reasonable NVMe starting point; reduce to 1 or 2 if chunk loading stutters.
* Keep lodYieldsToVanillaTransport, ping backstop, and send pacing enabled.
* LSS and DHSupport use independent channels and data models and may coexist.


ALTERNATIVE FABRIC SERVER MODS
------------------------------
1. VoxyServer
   Source: https://github.com/PooSmacker/VoxyServer

   VoxyServer embeds Voxy's world engine on a Fabric dedicated server. It
   voxelizes loaded chunks, imports existing region files, writes native Voxy
   RocksDB storage, streams level-0 sections, and pushes dirty updates. This is
   the direct consumer targeted by mca2lod --format voxy.

   Typical native storage path:
       <world>/voxyserver/<world_id>/storage/

   VoxyServer currently requires locally building against Voxy because Voxy's
   licensing does not permit bundling its source or binary in that repository.

2. Voxy Server Side branding
   Modrinth: https://modrinth.com/plugin/voxy-server-side

   The current Voxy Server Side artifacts are wire-compatible branded builds of
   the LSS implementation. Paper and Fabric artifacts may be available depending
   on the Minecraft release line. Prefer the original LSS project when evaluating
   source, protocol behavior, and operational documentation.


NATIVE VOXY STORAGE IMPLEMENTED IN THIS BRANCH
----------------------------------------------
Command:

    mca2lod --format voxy --map <WORLD> --output <EMPTY_STORAGE_DIRECTORY>

The backend writes:

* RocksDB column families: default, world_sections, id_mappings.
* Big-endian RocksDB section and mapping keys.
* Little-endian Voxy SaveLoadSystem3 section payloads.
* Gzip-compressed NBT block-state and biome identity mappings.
* Zstandard-compressed 32x32x32 voxel sections.
* Block-state properties, biome identities, sky light, and block light.
* Complete Voxy hierarchy levels 0, 1, 2, 3, and 4.
* Voxy-compatible opacity-priority 2x2x2 downsampling.
* Bounded producer/writer queues and atomic same-filesystem publication.

The output path must be empty, and the input must identify exactly one dimension
(one region/ directory). Generate separate databases for the Overworld, Nether,
and End. Never run the writer against a database opened by Minecraft, Voxy, or
VoxyServer; RocksDB uses an exclusive LOCK file.


CLIENT COMPATIBILITY
--------------------
Voxy relies on OpenGL compute-shader functionality beyond Apple's native OpenGL
4.1 implementation. Windows and Linux systems with modern NVIDIA, AMD, Intel Arc,
or sufficiently capable Mesa drivers are the practical targets. Native macOS
Voxy rendering is not currently a reliable deployment target. Distant Horizons
remains the appropriate renderer for the existing macOS client unless an
experimental translation stack is used.


DECISION MATRIX
---------------
Paper / Purpur server, Voxy clients:
    Use LOD Server Support.

Fabric server requiring a native pre-baked Voxy world database:
    Use VoxyServer plus mca2lod --format voxy.

Mixed DH and Voxy clients on Paper / Purpur:
    Run DHSupport and LSS together; tune their combined bandwidth and disk I/O.

macOS client:
    Prefer Distant Horizons. Voxy's native OpenGL compute path is unsupported.
